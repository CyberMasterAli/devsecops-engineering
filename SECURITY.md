# Contributing Guidelines

## Branch Naming

Use meaningful branch names:

- `feature/user-login`
- `fix/validation-error`
- `docs/week-1-report`
- `security/input-validation`
- `ci/security-scan`

## Commit Messages

Use clear commit messages:

- `docs: add Secure SDLC documentation`
- `security: update repository security policy`
- `fix: correct documentation error`
- `chore: initialize project repository`
- `ci: add security workflow`

## Pull-Request Process

1. Create a separate branch.
2. Make the required changes.
3. Review changes using `git diff`.
4. Create a meaningful commit.
5. Push the branch to GitHub.
6. Open a pull request.
7. Review the Files Changed tab.
8. Complete the security checklist.
9. Merge the approved change.

## Security Checklist

- [ ] No passwords, tokens, or private keys were added.
- [ ] Changes were reviewed.
- [ ] Documentation was updated.
- [ ] Commit messages are meaningful.
- [ ] Sensitive files are excluded.
- [ ] Screenshots contain no confidential information.
