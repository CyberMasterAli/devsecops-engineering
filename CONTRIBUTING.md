# Security Policy

## Supported Version

The latest version available on the main branch is currently supported.

## Reporting a Vulnerability

Do not create a public GitHub issue for an unpatched security vulnerability.

A vulnerability report should include:

- Description of the vulnerability
- Affected file or component
- Reproduction steps
- Potential impact
- Recommended solution, where available

## Sensitive Information

Do not include passwords, API keys, tokens, private keys, or personal
information in reports, issues, commits, or screenshots.

## Secret Exposure

An exposed credential must be revoked and replaced immediately. Removing it
from the latest version of a file is not sufficient because it may remain in
Git history.
